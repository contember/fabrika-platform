# @cloudflare/vite-plugin

## What it is

Cloudflare's official vite plugin: runs the Worker in dev under **real workerd**
(miniflare), emulating D1/KV/R2/Queue/Cron locally from `wrangler.jsonc`. The
real-CF dev path (vs lopata's Bun-based emulation).

## When & why to use

- You use more/fresher CF primitives than lopata emulates (Queue, AE-adjacent, etc.) and want production-fidelity local behavior.
- The cf-fat path.

## When NOT to use

- You want the lightest local-first loop with the lopata dashboard and don't need workerd fidelity → use `lopata`.

## Impacts & gotchas

- `vite.config.ts`: `@cloudflare/vite-plugin` + the RRv7 plugin, SSR environment configured for Workers. Verify options against installed versions.
- Reads bindings from `wrangler.jsonc` (generated by `oblaka`); local D1 via `wrangler d1 … --local`.
- **`analytics-engine` is still not emulated** even here — counts go through `count-store`.

## Relationships — why

- **requires `cloudflare` + `vite` + `wrangler`** (workerd/miniflare + CLI).
- **conflicts `lopata`** — same `cf-dev-runtime` slot; pick one dev runtime (often env-toggled with `CF=1`). **`lopata` is our preferred default**; use this plugin when you specifically need workerd fidelity (e.g. Queue/Cron) lopata doesn't emulate yet.
