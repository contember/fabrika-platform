# Cloudflare R2

## What it is

S3-compatible object storage with no egress fees. Used for **large/append-style
payloads** — full event bodies, uploads, source maps — keyed by id. Bound as
`env.R2`.

## When & why to use

- Storing payloads too big or too numerous for D1 rows (event bodies, files, source maps).
- Write-heavy blob ingest, especially batched through a `queue`.

## When NOT to use

- Small structured records you query by field → `d1`. Hot small keys → `kv`.

## Impacts & gotchas

- Objects are addressed by key; design a stable key scheme (e.g. `events/<projectId>/<id>`).
- Pair with `queue` for bursty writes: enqueue → consumer batches puts to R2 (keeps the request path fast). See `write-split`.

## Relationships — why

- **requires `cloudflare`** — CF binding. **recommends `oblaka`** (declare `R2Bucket`) and **`queue`** (buffer bursty payload writes).
